# P0 Reasoning and Evidence Contract

Status: `0.2-draft`, portable document contract with a small structural checker.
It does not imply that scLucid exposes these objects as Python APIs. Read
[Minimum handoff](handoff-minimum.md) for exact checked fields, examples and
explicit migration from the earlier documentation-only `0.1-draft`.

## Contents

- Contract ownership
- ReasoningBrief
- WorkflowReview
- RunEvidence
- Handoff and compatibility rules

## Contract Ownership

| Object | Producer | Consumer | Owns |
| --- | --- | --- | --- |
| `ReasoningBrief` | `scientific-reasoning` | workflow reviewer or software | question, estimand, evidence needs, alternatives, falsifiers, claim boundary |
| `WorkflowReview` | `scrna-analysis-core` | analyst or scLucid | workflow feasibility, parameter decisions, diagnostics, results guide, rerun scope |
| `RunEvidence` | scLucid or another executor | scientific reasoning and claim audit | executed method, artifact, result, uncertainty, sensitivity, evidence status |

The producer owns meaning. A downstream layer may report that a field is
missing or infeasible but must not silently redefine it.

```yaml
  supported: []
  exploratory: []
  unsupported: []
```


`WorkflowReview` evaluates whether the requested evidence can be generated by
the available scRNA-seq design and artifacts. It must not promote exploratory
evidence into a stronger claim.

## RunEvidence

```yaml
schema_name: RunEvidence
schema_version: 0.2-draft
evidence_id: E1
question_id: Q1
run_id: null
execution_status: null
stage: null
artifact:
  path_or_key: null
  representation: null
method:
  name: null
  version: null
  parameters: {}
result:
  summary: null
  effect: null
  uncertainty: null
  experimental_unit: null
sensitivity: []
quality_status: REVIEW
supports: []
challenges: []
limitations: []
```

`RunEvidence` records what was actually executed and observed. It is not
itself a mechanistic or clinical conclusion.

The RunEvidence block is a template, not a valid run record while run_id,
execution_status, method.name, artifact.path_or_key or result.summary are null.
Set execution_status to completed or failed only after execution; a planned
analysis remains in WorkflowReview. Record an unknown method version as null
with a limitation rather than inventing a version.

## Handoff and Compatibility Rules

1. Keep the three schemas separately versioned.
2. Preserve identifiers and provenance across every transformation.
3. Do not overload `ProjectContext.study_objective` with the complete brief.
4. Allow unknown scientific fields as null; report their consequences. Preserve
   the minimum identity/structure fields needed for a machine-checked handoff.
5. Keep existing scLucid workflows functional when no `ReasoningBrief` is
   provided.
6. Treat `BLOCKED`, `REVIEW`, `READY`, and `NOT_RUN` as use-specific
   evidence states, not biological truth.
7. Structural checks do not establish actual execution, scientific validity or
   scLucid compatibility. Validate those separately before adopting a public API.
8. Keep expert-lens selection as process metadata outside the P0 schemas.
   Researcher identity, reputation, or panel agreement is not evidence.
