# Exploratory project working agreements

- Read `PROJECT_NOTES.md` before substantive work. Load linked records only when
  relevant. Respect their recorded access restrictions.
- After meaningful work, update only the sections whose facts changed. Keep the
  question, real inputs, actual actions, observations, limits and next step
  resumable in that one file. Record important changes of interpretation without
  erasing their earlier basis; use dated entries or links to existing records.
- Clearly label planned, attempted, completed and checked work. Never turn an
  observation, a successful command or a structure audit into a claim of
  scientific validity. Record the experimental unit and comparison when making
  statistical claims; preserve uncertainty and alternative explanations.
- Protect raw/source data wherever they are stored. Do not modify them in place.
  Preserve unrelated changes and existing paths; do not move, overwrite or
  delete substantive files without authorization. Do not write credentials,
  access tokens or direct personal identifiers into project memory.
- For actual analyses, record the input identity, code or notebook entry point,
  relevant settings, environment/reference versions and output location to the
  extent known. State missing provenance explicitly. A normal relative link to
  an existing log or record is enough; do not duplicate that record.
- Use the tools needed for the task. scLucid, other skills and formal readiness
  reports are optional for maintaining these exploratory records. Their absence
  does not prevent core project management or authorize scientific claims.
- Do not generate a full formal status set for each exploration. When scope
  expands to durable multi-run analysis, publication delivery or collaboration,
  assess whether a research/manuscript profile is appropriate. Keep these notes
  as historical evidence and use a reviewed retrofit; do not relocate files or
  silently assign a formal layout version.
- Report the work actually done, checks actually run, remaining limits and next
  useful step. Update the notes date only after reviewing/updating the record.
